# Aegis Hypothesis Validation Workflow Requirements

## Purpose

Define the autonomous hypothesis validation workflow for Aegis Research Lab.

The operator does not want to manually review research recommendations before validation. If a hypothesis qualifies, Aegis should automatically create a paper-testing sleeve, link the relevant symbols, and track validation results.

This document defines the workflow from hypothesis to paper validation.

It is not a trade-advice, live-trading, or broker-execution document.

## Core Principle

Research Lab is an autonomous research and validation engine.

The operator should not be required to manually approve a hypothesis before paper validation begins.

If a hypothesis qualifies for paper testing, Aegis should:

1. create a paper-testing sleeve,
2. link relevant symbols,
3. generate paper-validation candidates,
4. track results,
5. report validation outcomes.

Human review should occur after validation evidence exists, not before paper testing begins.

## Intended Workflow

The canonical lifecycle is:

```text
HYPOTHESIS_CREATED
    ↓
RESEARCH_QUEUED
    ↓
RESEARCH_RUNNING
    ↓
EVIDENCE_COLLECTED
    ↓
QUALIFICATION_EVALUATED
    ↓
QUALIFIED_FOR_PAPER_VALIDATION
    ↓
PAPER_TESTING_SLEEVE_CREATED
    ↓
SYMBOLS_LINKED
    ↓
PAPER_VALIDATION_ACTIVE
    ↓
VALIDATION_RESULTS_READY
    ↓
VALIDATED | REJECTED | INCONCLUSIVE | RETIRED
```

## Operator Involvement Policy

The operator should not be required for:

* starting research,
* reviewing research before validation,
* approving qualification,
* creating the paper-testing sleeve,
* linking symbols,
* starting paper validation.

The operator may review:

* validation results,
* blocked states,
* safety warnings,
* final findings,
* evidence summaries.

## Human Review Boundary

Human review belongs after:

```text
VALIDATION_RESULTS_READY
```

not at:

```text
RECOMMENDATION_READY
```

The state `RECOMMENDATION_READY` should not be treated as a terminal manual-review state if the hypothesis qualifies for paper validation.

## Qualification Criteria

A hypothesis qualifies for paper validation only if it meets explicit criteria.

Required qualification dimensions:

* evidence sufficiency,
* data freshness,
* affected symbols identified,
* testable signal definition,
* paper-trade construction feasibility,
* risk guardrails,
* duplicate/same-symbol policy,
* sleeve uniqueness,
* no live/broker execution required.

The qualification result must be one of:

* `QUALIFIED_FOR_PAPER_VALIDATION`
* `NOT_QUALIFIED`
* `QUALIFICATION_BLOCKED`
* `MORE_RESEARCH_REQUIRED`
* `INCONCLUSIVE`

## Required Qualification Artifact

Create/document:

```text
truth/reports/aegis_hypothesis_qualification_v1/<day>/hypothesis_qualification.v1.json
```

Each row must include:

* hypothesis_id
* research_run_id
* title
* qualification_status
* qualification_score
* confidence
* evidence_sufficiency
* data_freshness
* affected_symbols
* testable_signal_definition
* paper_validation_allowed
* blocker_reasons
* required_follow_up
* generated_at
* source_artifacts

## Paper-Testing Sleeve Creation

If a hypothesis qualifies, Aegis must automatically create or reuse a paper-testing sleeve.

Required artifact:

```text
truth/reports/aegis_paper_testing_sleeve_v1/<day>/paper_testing_sleeve.v1.json
```

Each sleeve must include:

* sleeve_id
* hypothesis_id
* research_run_id
* sleeve_name
* sleeve_type: `PAPER_TESTING`
* lifecycle_state
* linked_symbols
* test_start_date
* test_end_date or review_after_days
* validation_rules
* entry_rules
* exit_rules
* risk_limits
* duplicate_policy
* source_artifacts
* generated_at

## Symbol Linking

A qualified hypothesis must link symbols explicitly.

Symbol link statuses:

* `LINKED`
* `EXCLUDED_DUPLICATE`
* `EXCLUDED_MISSING_DATA`
* `EXCLUDED_NOT_TESTABLE`
* `EXCLUDED_RISK_POLICY`
* `EXCLUDED_MANUAL_REVIEW_REQUIRED`

Each linked symbol must include:

* symbol
* role
* reason_linked
* evidence_reference
* validation_eligibility
* paper_candidate_allowed
* exclusion_reason if excluded

## Paper Validation Candidate Generation

A paper-testing sleeve may generate paper-validation candidates only when:

* hypothesis is qualified,
* sleeve exists,
* symbols are linked,
* market data is current,
* construction inputs are valid,
* duplicate policy allows,
* paper mode is enabled.

Candidates generated by a paper-testing sleeve must be tagged with:

* hypothesis_id
* research_run_id
* paper_testing_sleeve_id
* validation_phase
* source_evidence

## Safety Rules

This workflow may create paper-testing sleeves and paper-validation candidates only.

It must not:

* create live broker orders,
* submit/transmit trades,
* enable autonomous live trading,
* bypass paper safety gates,
* produce trade advice requiring execution,
* modify existing production sleeves without explicit policy.

Live broker submit/transmit and autonomous trading remain disabled.

## Research Review Role

Research Review should not block qualified paper validation.

Research Review should show:

* what was qualified,
* what paper-testing sleeve was created,
* which symbols were linked,
* why the hypothesis qualified,
* current validation state.

Research Review should not be the manual gate before paper validation.

## UI Requirements

Research Lab must show clear sections:

1. Research Queue
2. Qualified for Paper Validation
3. Paper Testing Sleeves
4. Validation Active
5. Validation Results Ready
6. Blocked / Needs Attention

The operator should immediately see:

* which hypotheses are researching,
* which are queued,
* which qualified,
* which testing sleeves were created,
* which symbols are linked,
* which validations are active,
* which results are ready.

## Replacing Ambiguous Statuses

Avoid operator-facing states such as:

* `Recommendation Ready`
* `Manual review required`

unless manual intervention is truly required.

Use clearer states:

* `Research Complete`
* `Qualified for Paper Validation`
* `Paper Testing Active`
* `Validation Results Ready`
* `Blocked: Missing Evidence`
* `More Research Required`

## Required Commands

Add/document:

```bash
npm run aegis:hypothesis-qualification
```

Builds hypothesis qualification artifact.

```bash
npm run aegis:paper-testing-sleeves
```

Creates or updates paper-testing sleeves for qualified hypotheses.

```bash
npm run aegis:hypothesis-validation-status
```

Prints:

* total hypotheses
* researching
* qualified
* not qualified
* more research required
* paper-testing sleeves active
* linked symbols
* validation candidates generated
* blocked reasons

## Required Self-Check

Add/document:

```bash
npm run aegis:hypothesis-validation-self-check
```

It must fail if:

* qualified hypothesis has no paper-testing sleeve,
* paper-testing sleeve has no linked symbols,
* linked symbol lacks evidence reference,
* paper-validation candidate lacks hypothesis_id,
* validation state is ambiguous,
* manual review blocks qualification without explicit policy,
* Recommendation Ready appears as terminal state for qualified hypothesis,
* live/broker/autonomous trading gates are enabled.

## Acceptance Tests

Add tests proving:

* qualified hypothesis automatically creates paper-testing sleeve,
* sleeve links affected symbols,
* unqualified hypothesis does not create sleeve,
* missing evidence produces QUALIFICATION_BLOCKED,
* duplicate symbols are excluded or classified,
* paper-validation candidates include hypothesis_id and sleeve_id,
* Research Review does not block qualified validation,
* UI shows Paper Testing Active without operator approval,
* live trading remains disabled,
* no hypothesis silently stalls in Recommendation Ready.

## Auditability Requirements

Every qualification and sleeve creation must be auditable.

Required trace:

```text
hypothesis_id
→ research_run_id
→ evidence artifacts
→ qualification artifact
→ paper_testing_sleeve_id
→ linked symbols
→ validation candidates
→ paper results
→ validation outcome
```

Every transition must include:

* timestamp
* source artifact
* decision reason
* status
* actor: `SYSTEM` or `OPERATOR`
* safety gates checked

## Determinism Requirements

Qualification must be deterministic.

Same inputs must produce same qualification status.

Qualification thresholds must be explicit and configurable.

No freeform-only LLM output may be the sole basis for qualification.

Structured qualification fields are required.

## Governance Rule

A hypothesis that qualifies for paper validation must not wait for operator approval before creating a paper-testing sleeve, unless an explicit safety blocker exists.

Operator review is for validation results, not for starting paper validation.

`aegis/modules/operator_portal/aegis.module.yaml` must reference this document as the authority for autonomous hypothesis validation workflow.
