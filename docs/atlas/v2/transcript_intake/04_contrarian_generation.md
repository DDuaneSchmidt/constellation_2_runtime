# Contrarian Generation

Contrarian theory generation uses the existing `ExternalStrategyContrarianTheory` flow after claim extraction, mechanism classification, and deduplication.

Contrarian output names plausible failure modes and falsification tests. It must not treat transcript claims as proof. It must not imply profitability, validation, or recommendation.

If rules are vague, the contrarian status remains clarification-oriented rather than validation-oriented.
